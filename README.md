# SAINT-VEIL · 재가 되어버린 고체(固體)

GitHub Pages용 세계관·캐릭터 안내 홈페이지 **2차 디자인**입니다. 게임 메뉴 + 미니홈피 느낌을 적용했고, 별도 빌드 도구 없이 HTML/CSS/JavaScript만으로 작동합니다.

## 이번 버전 변경점

- 첫 화면의 잘리는 3분할 이미지를 **어두운 단색 계열 타이틀 화면**으로 교체. 캐릭터 선택 카드와 `ENTER WORLD` 버튼을 추가했습니다.
- 본문에 미니홈피 프로필, 메뉴, 메모장 모티브를 추가했습니다.
- 기존 세계관 11개 항목, 인트로, 캐릭터 소개, 유저 프로필, 제작자 안내, 검색·접기·복사를 유지했습니다.
- `ALBUM`: 기존 공개 인장 3장을 기본 표시하고, GitHub 공개 이미지 폴더에 올린 파일을 자동으로 읽습니다.
- `studio.html`: 이미지 미리보기·캐릭터 분류·파일명 수정·공개/보관 후보/교체/미사용 상태 지정과 공개용·개인 백업용 ZIP 다운로드 기능을 추가했습니다.

## 포함된 파일

- `index.html` — 홈페이지
- `styles.css`, `theme-v2.css` — 기존 스타일 + 2차 게임·미니홈피 테마
- `script.js` — 기존 진행 기능
- `gallery.js` — 공개 앨범 자동 불러오기 + 필터 + 원본 보기
- `config.js` — GitHub 계정·저장소 설정 (대부분 자동 인식)
- `studio.html`, `studio.css`, `studio.js` — 개인 이미지 정리실
- `assets/{ash,ian,luca}.webp` — 인장 원본을 가볍게 변환한 웹용 이미지
- `assets/gallery/{ash,ian,luca,world}/.gitkeep` — 각 공개 갤러리 기본 폴더
- `.nojekyll` — GitHub Pages 정적 파일 공개 설정

## GitHub Pages 게시

**중요: 기존 사이트를 업그레이드한다면 새 파일로 덮어씁니다.** `index.html`, CSS, JS 등을 해당 저장소 **루트**에 올리고 `assets` 폴더도 유지해 주세요. ZIP 자체를 저장소에 올리는 게 아니라, **압축을 풀어 나온 파일과 폴더**를 올려야 합니다.

1. 사이트를 공개할 **다른 GitHub 계정**에 로그인합니다.
2. 새 공개 저장소를 만들거나, 이미 만든 홈페이지 저장소를 엽니다. 저장소 이름은 자유입니다.
3. ZIP 내부의 모든 파일을 저장소 최상위 폴더(root)에 업로드/커밋합니다. 숨김 파일인 `.nojekyll`도 유지합니다.
4. GitHub **Settings → Pages → Build and deployment → Deploy from a branch → main / (root)** 설정을 확인합니다.
5. 주소 예시: `https://다른계정.github.io/저장소이름/` (정확한 주소는 GitHub의 Pages 설정에서 확인).
6. 해당 주소를 리핀 제작자 코멘트에 기재합니다.

이미지 앨범은 GitHub Pages 주소에서 **계정과 저장소 이름을 자동 인식**합니다. 다만 사용자 지정 도메인이나 배포 분기(`main` 외)를 쓰는 경우 `config.js`의 `owner`, `repo`, `branch`를 직접 설정해 주세요.

## 이미지를 올리는 방법 — 공개 앨범

1. 홈페이지에서 `ALBUM → 이미지 정리실 열기`를 클릭해 `studio.html`을 엽니다.
2. 파일을 드래그하거나 여러 장을 선택합니다. **기본 상태는 보관 후보**이며, 선택과 분류는 현재 브라우저에서만 임시로 진행됩니다.
3. 공개하려는 파일만 **상태: 공개**로 변경하고, `애쉬`, `이안`, `루카`, `월드·기타` 중 카테고리를 고릅니다. 파일명도 바꿀 수 있습니다.
4. **공개용 ZIP**을 다운로드한 뒤 압축을 풉니다. 폴더별 이미지가 `assets/gallery/ash`, `ian`, `luca`, `world`로 정리됩니다.
5. 실제 홈페이지의 **GitHub 저장소**에서 각 폴더를 열고 **Add file → Upload files**로 해당 이미지들을 업로드·커밋합니다.
6. GitHub Pages 반영 후 사이트의 `ALBUM`에 이미지가 자동으로 나타납니다. 홈페이지 자체에서 로그인하거나 토큰을 입력할 필요는 없습니다.

**주의:** `studio.html`에서 파일을 선택하는 것은 GitHub 서버 업로드가 아닙니다. GitHub Pages는 서버 측 저장 기능이 없기 때문에 GitHub에 커밋하는 단계가 필요합니다.

## 교체/미사용 백업 — 개인 보관

- 상태를 `교체 이미지`, `미사용 이미지`, `보관 후보` 등으로 지정합니다.
- **전체 백업 ZIP**을 다운로드하면 상태와 캐릭터에 따라 `archive/<상태>/<캐릭터>/`에 분류된 파일 및 `분류목록.json`이 들어갑니다.
- 이 ZIP은 **개인 PC 또는 별도 비공개 GitHub 저장소/드라이브**에 보관하세요. **공개 홈페이지 저장소에 업로드하지 마세요.**
- 변경 이전 공개 이미지를 사이트 저장소에서 제거해도 **공개 Git 기록에는 예전 파일이 남아 있을 수 있습니다.** 처음부터 비공개로 남겨야 할 사진은 공개 저장소에 한 번도 올리지 않는 것이 안전합니다.
- 브라우저 탭을 닫거나 새로고침하면 정리 중 파일 목록이 사라집니다. **내보내기를 먼저 해 주세요.**

## 문제 해결

- `ALBUM`에 신규 이미지가 보이지 않으면 GitHub 저장소 경로, Pages 배포 상태, `config.js`의 `owner/repo/branch`, 파일 확장자를 확인해 주세요.
- 공개 앨범이 비어도 기본 인장 3장은 표시됩니다.
- PNG/JPG/WEBP/GIF 파일을 권장합니다. 업로드 이미지는 많아질수록 로딩이 느려질 수 있으니 WEBP 등으로 최적화하면 좋아요.
- 파일 이름에 `/`, `\\`, `:`, `?` 등이 있으면 내보내기 과정에서 `_`로 변경됩니다.
- 외부 도메인이나 커스텀 빌드/하위 경로 구조를 쓰면 경로를 직접 조정해야 할 수 있습니다.

**공개되는 내용은 누구나 다운로드할 수 있습니다.** 이 버전에는 비밀 로어북과 성인용 이미지를 포함하지 않았습니다.
